## 为什么做这个

想记个账，结果发现市面上的方案都有点别扭：

- 行情工具大多是 **Python 生态**，为了看个持仓得先配环境；
- 在线记账要**把持仓交给别人的服务器**；
- 表格里记基金定投最麻烦 —— 得自己按每个交易日的净值把金额折算成份额，漏一天就永远对不上。

所以做了这个：**双击一个文件 → 浏览器打开 → 开始记账**。没有后端服务要部署，没有数据库要装，持仓明细就一个 JSON 文件躺在你自己的硬盘上。

## 功能

### 五个板块

| 板块 | 能做什么 |
|---|---|
| **总览** | 总市值 / 总成本 / 累计盈亏、持仓配置条与权重、账目流水 |
| **股票** | 持股数量 + 成本价，一键更新股价；自动算浮动盈亏与「自上次更新」的涨跌 |
| **基金** | 份额 + 成本价，**每只基金可单独开启日定投**，按交易日净值自动折算份额 |
| **加密货币** | 数量 + 成本价（USD / CNY 计价），市值统一折算成人民币；四个行情源自动降级 |
| **设置** | 高对比度开关、重建演示 / 清空数据、运行环境与数据来源信息 |

三个持仓板块都支持**屏蔽某一项资产**（见下一节）。

### 屏蔽某一项资产

想把某个实验仓位、某个券商账户暂时从视野里拿掉，又不想删记录时用它。

**屏蔽 = 暂不计入合计，不会丢任何数据。**

- 每行末尾点 **「屏蔽」**（抽屉表单里也有「屏蔽这一项」开关）；
- 顶部会出现**屏蔽条**，把「屏蔽之后的整体内容」摆出来：
  `整体内容（不含屏蔽项）：市值 ¥… · 成本 ¥… · 盈亏 +¥…（+…%） · 已排除 ¥…（成本 ¥…）`
- 屏蔽项**不计入任何合计** —— 总市值 / 总成本 / 盈亏 / 收益率 / 权重 / 配置条 / 定投合计
  全部只看未屏蔽的部分，权重会自动重新归一；
- **持仓、成本价、总成本、备注、定投配置、已取到的行情价，全部原样保留。**
  屏蔽项的行照样显示真实数字（半透明 + `已屏蔽` 标注），你能一眼看出它现在值多少，
  只是没算进合计；
- 屏蔽期间**更新行情会跳过它**：不取价、不补定投，行情就停在屏蔽那一刻。
  这样既省掉没必要的接口调用，也不会让屏蔽项拖慢整次更新；
- 点 **「取消屏蔽」立刻还原** —— 所有数字回到屏蔽前的样子，**不需要重新拉一次行情**。

> 只有「定投」这一项会真的停下来：屏蔽期间不补算，恢复后下次更新会把
> (上次定投日, 最新净值日] 之间欠的交易日一次性补齐（和平时一样幂等，不会重复扣）。

### 你不用自己算的几件事

- **定投按交易日结算**：节假日自动跳过，净值没公布的那天会自动留到下次更新补上，**不会漏也不会重复扣**；
- **「自上次更新」是真实窗口涨跌**：用上次更新时存下来的价格作基准，而不是当天的涨跌幅 —— 隔一周再打开，看到的就是这一周的累计变化；
- **均价自动维护**：定投持续累加总成本，持仓均价由 `总成本 ÷ 份额` 反推。

3. 首次运行会自动安装行情依赖，随后浏览器自动打开面板。

用的时候别关那个黑色命令行窗口 —— 关掉它 = 停止服务。想换端口：`set STOCKVIEW_PORT=4000 && npm start`。

### 二、从源码跑

```bash
git clone https://github.com/Justin-Mai/stockview.git
cd stockview
npm install
npm start            # 启动并自动打开浏览器
```

### 三、重新构建图标与启动器（可选）

## 定投是怎么算的

这是整个项目最核心的一块。每次点「更新净值 & 定投」，程序会取出 `(上次定投日, 最新已公布净值日]` 之间的**每一个 A 股交易日**，按当日单位净值把金额折算成份额：

```
新增份额   = 当日定投金额 ÷ 当日单位净值
新持有份额 = 原份额 + Σ 每个交易日的新增份额
新总成本   = 原总成本 + Σ 每日定投金额
持仓均价   = 总成本 ÷ 持有份额
```

几个刻意的设计：

- **只认已公布的净值**。场外基金当日净值一般晚上才出，所以白天的更新只会补「昨天及以前」的交易日，今天那笔留到下次更新自动补上 —— 界面上直接显示**还有几个交易日待补定投**。
- **没有净值就记一笔跳过**。某天基金暂停申赎、没有公布净值，程序把它标记为已跳过，不会反复重试、也不会算错。
- **幂等**。连续点两次更新不会重复扣款，`npm run selftest` 里有专门一步验证这点。

> 实测：2026-09-25（中秋）不是交易日，程序正确地没有扣款。

## 行情数据从哪来

### 股票 / 基金 —— [stock-sdk](https://github.com/chengzuopeng/stock-sdk)

零依赖的 JS 行情 SDK，浏览器和 Node 都能跑。本项目用到：

| 用途 | 接口 |
|---|---|
| A 股实时行情 | `sdk.quotes.cnSimple()` |
| 公募基金实时净值 | `sdk.quotes.fund()` |
| 历史日线 | `sdk.kline.cn()` |
| **基金历史净值**（定投折算的依据） | `sdk.fund.navHistory()` |
| **交易日历** | `sdk.reference.tradingCalendar()` |
| 代码 / 名称 / 拼音搜索 | `sdk.search()` |

底层是腾讯财经 / 东方财富的公开接口，**非实时撮合，通常有数十秒到数分钟延迟** —— 适合记账估值，不适合高频交易决策。

### 加密货币 —— 四源自动降级

加密货币的公开接口在受限网络下的可用性差异极大（**DNS 污染**比「被墙」更常见），
所以这里不是「一个主源 + 一个备用」，而是**四个源按可用性依次降级**：
任一个超时、限流、返回空、或者根本没有这个交易对，都会自动往下走。

| 顺序 | 源 | 端点 | 定位 |
|---|---|---|---|
| 1 | **Binance 公开行情** | `data-api.binance.vision` | 一次批量拿全部币价，无额度限制 → **首选** |
| 2 | **Gate.io 现货** | `api.gateio.ws` | 一次批量拿全部交易对，覆盖面最广 |
| 3 | OKX 现货 | `www.okx.com` | 逐交易对查询，部分网络可直连 |
| 4 | CoinGecko | `api.coingecko.com` | 免费额度最小 → 兜底 |

**为什么不把 CoinGecko / OKX 当主源**（本机实测）：

```
api.coingecko.com  → 108.160.170.52   （解析到 Dropbox 的 IP，TCP 443 连不上）
www.okx.com        → 169.254.0.2      （链路本地地址，明显被污染）
api.binance.com    → 451 地区限制
data-api.binance.vision → ✅ 200      （官方公开行情域名，可用）
api.gateio.ws      → ✅ 200
```

两个「看起来能用」的域名实际都连不上。一旦被选为第一个源，每次更新都要先等它超时 ——
这就是早期版本「点更新后转 80 多秒、最后 5 个币全军覆没」的直接原因。

配套的三个机制：

- **熔断**：某个源连续失败 2 次后进入 5 分钟冷却，冷却期内直接跳过。
  被污染的域名只会让你付出**一次**超时的代价，而不是每次更新都付。
- **批量**：Binance / Gate.io 都支持一次请求取回所有交易对，5 个币只需 1 次 HTTP 请求；
  查不到的币再交给下一个源补。
- **交易对校验**：先拉交易所的交易对清单再发请求，避免「不存在的交易对」。
  这里踩过一个坑：CoinGecko 的 id `tether` → 符号 `USDT` → 拼出 `USDTUSDT`，
  而 Binance 对「批量查询里混进一个非法 symbol」返回的是
  `HTTP 400 {"code":-1121,"msg":"Invalid symbol."}` —— **整批都拿不到**。
  现在稳定币会显式换成另一种稳定币计价（`USDTUSDC`），必要时还会自动取倒数。

USD/CNY 汇率的顺序刻意是**法币汇率源优先**：
[frankfurter](https://www.frankfurter.app)（欧洲央行）→ [er-api](https://open.er-api.com)
→ CoinGecko（USDT 报价推导）。早期把 CoinGecko 放第一位，它一挂汇率就掉到硬编码的 7.1，
数据文件里因此出现过「早上存 6.7045、晚上又变 7.1」这种来回跳变。

```
│   ├── tasks.js              ← 长任务进度追踪
│   ├── seed.js               ← 演示数据构造
│   ├── util.js               ← 日期 / 精度 / 并发 / 缓存工具
│   └── providers/
│       ├── cn.js             ← A 股 / 基金（stock-sdk）
│       └── crypto.js         ← 加密货币（Binance / Gate.io / OKX / CoinGecko 四源降级）
├── web/                      ← 前端，原生 HTML/CSS/JS，无构建步骤
├── scripts/                  ← 图标生成、启动器编译、四个自检脚本

```

**技术选型上刻意的克制**：前端不用框架、不用打包器，后端**只装一个运行时依赖**（stock-sdk）。目的是让这个项目十年后还能打开就用，而不是先跟依赖版本打架。

## HTTP 接口

服务默认跑在 `127.0.0.1:3939`（端口被占用会自动顺延）。前端就是这套 API 的一个消费者，你也可以直接调：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 完整快照（含估值、权重、屏蔽统计、定投统计、流水） |
| POST | `/api/assets` | 新增资产 `{scope, data}` |
| PATCH | `/api/assets` | 修改资产 `{scope, id, data}`（`data.hidden` 可切换屏蔽） |
| DELETE | `/api/assets?scope=&id=` | 删除资产 |
| POST | `/api/assets/hidden` | 屏蔽 / 取消屏蔽 `{scope, id, hidden}` |
| POST | `/api/update` | 执行更新 `{scope: 'stock'\|'fund'\|'crypto'\|'all'}` |
| POST | `/api/update/cancel` | 中止进行中的更新（立即返回，加密货币源可被真正中断） |
| GET | `/api/lookup?scope=&code=` | 新增前预览行情 |
| GET | `/api/search?scope=&q=` | 代码 / 名称联想 |
| POST | `/api/reset` | `{mode:'empty'\|'demo'}` 清空或重建演示数据 |
| GET | `/api/task` | 当前长任务进度（前端轮询显示实时步骤） |

> `/api/update` 期间 `/api/state` 与 `/api/task` 仍然**立即返回**：
> 联网过程不占 store 的串行读写队列，否则更新 5 秒就会把整页堵 5 秒，
> 遮罩上的进度也会卡在第 0 步不动。

## 常见问题

**Q：点了更新，基金份额没变？**
看顶部提示「还有几个交易日待补定投」。场外基金当日净值一般 20:00 后才公布，白天的更新只补昨天及以前。

**Q：点了「重建演示数据」感觉没反应？**
它要联网抓 8 个标的的行情，实测约 **2.5 秒**。点击后会弹出遮罩并实时显示进度（进度来自服务端 `/api/task`，不是假动画）；「清空数据」是纯本地操作，50 毫秒完成。

![重建演示的进度](screenshots/06-progress.png)

**Q：遮罩上那个绕着印章转的圈是什么？**
是「正在跑」的指示器：圆形印章外面一圈同心圆环，只亮一段暖光并匀速绕圈，
和按钮上的旋转指示器是同一套语言 —— 静止的一帧也是完整一个圆，所以看起来不会像缺了一角。
系统开了「减少动态效果」时会退化成呼吸明暗，仍然能看出程序在跑。

**Q：更新失败 / 取不到价格？**
行情源都是公开接口，偶发限流或被墙。加密货币会按 Binance → Gate.io → OKX → CoinGecko
自动降级，某个源连续失败会被熔断 5 分钟（提示里会写「已熔断，N 秒后重试」），
汇率会依次换源，股票基金可稍后重试。

**Q：更新太久，能中途放弃吗？**
遮罩上有「中止更新」按钮（调 `/api/update/cancel`）。中止后**不会**推进「上次更新」日期，
也不写盘，所以下次更新仍以原来的基准计算，不会算漏一段行情。
加密货币这类可中断的源会立刻停；股票 / 基金正在飞的那一个请求会跑完，然后停下。

**Q：屏蔽某一项之后，我的成本价 / 持仓会不会被清掉？**
不会。屏蔽只是把这一项从合计里拿掉，**持仓、成本价、总成本、备注、定投配置、
已取到的行情价全部原样保留**，行里照样显示真实数字（半透明 + `已屏蔽` 标注）。
取消屏蔽立刻还原，**不需要再点一次「更新行情」**。

**Q：屏蔽项会跟着行情一起更新吗？**
不会。更新行情时直接跳过它（提示里会写「已屏蔽跳过 N 项」），所以行情停在屏蔽那一刻 ——
既省掉没必要的接口调用，也不会让屏蔽项拖慢整次更新。
唯一会「停下来」的是定投：屏蔽期间不补算，恢复后下次更新会一次性补齐欠的交易日（仍然幂等）。

**Q：数据存哪？会上传吗？**
只存在 `data/portfolio.json`，不会上传到任何地方。复制这个文件就是备份。写入采用「临时文件 + 原子重命名」，文件损坏时会自动留档到 `data/backups/`。

**Q：成本价和总成本是什么关系？**
`总成本 = 数量 × 成本价`。基金开启定投后总成本持续累加。修改资产时**只提交你真正改过的字段** —— 只改「总成本」就不会被成本价覆盖。

**Q：可以同时开两个实例吗？**
不建议。两个实例共用一个 `data/portfolio.json`，写盘本身是原子的（临时文件 + 重命名），但「读—改—写」之间**没有跨进程锁**，同时操作可能互相覆盖。要换端口重开，先关掉旧窗口。启动时若 3939 被占用，程序会自动顺延到 3940、3941…，看窗口里打印的地址即可。

## 工程笔记

几个踩过的坑，都是**只看代码发现不了、必须实测**的那类，留个记录。

**1. 备用源返回 HTTP 200，但其实是空的。**
OKX 的交易对是 `BTC-USDT`，而我一开始用 CoinGecko 的币种 id 去猜，发出了 `BITCOIN-USDT`。
问题在于 OKX 对不存在的交易对返回的是 **200 + `{"code":"51001","data":[]}`**，不抛异常 ——
于是「自动切换备用源」这个特性**静默失效**，还因为代码不报错而一直没被发现。
现在按「调用方提示 → 内置币种表 → id 大写」三级解析符号，并用「把返回价换算回 USDT 与 OKX 日线收盘比对」的方式验证来源。

**2. 缓存函数没有按参数区分。**
`memo(fn)` 一开始只存了一个值，于是 `getPrices(['bitcoin'])` 之后 60 秒内调
`getPrices(['ethereum'])` 会拿到**比特币的结果**。已改为按序列化后的参数分别缓存。

**3. 图标的字看起来偏左上，量出来确实偏了。**
`DrawString` 的 Center 对齐居中的是**字身宽度**而不是**墨迹**，再加上我手调的一个「视觉补偿」，
结果 256px 上字形**纵向偏高 10px**（占画布 4%）。现在改成闭环：画 → 扫描像素量墨迹边界 →
反推位移 → 画进成品 → 与「只有底色」的版本相减量残差 → 修正，直到 ≤0.5px（像素栅格的理论极限）。
`npm run icon` 每次都会打印每个尺寸的实测残差。

**4. Windows 的 .bat 不能带自定义图标。**
它不是可执行文件，没有资源段。资源管理器显示的图标来自文件类型关联（`HKCR\batfile`），全局生效、无法逐文件定制。
所以本项目编译了一个几 KB 的启动器 exe，把图标作为资源嵌进去，**启动逻辑仍然只有 `启动.bat` 一份**，不会出现两套实现。

**5. PowerShell 的 `[int]` 是四舍五入，不是截断。**
写 ICO 的 AND 掩码时用 `[int]($x / 8)` 取字节下标，每行最后一个像素会**多算一格**导致越界。
改用位移 `($x -shr 3)`。

**6. 数据文件莫名涨到 742KB。**
原因是 `fundNavHistory()` 返回的是基金**成立以来的全量净值**（老基金有 3895 条），
而演示数据构造直接把它整个存了进去，绕过了更新时的截断逻辑。统一收口后：**742KB → 57KB**。

**7. 限流器把整条 Promise 链「毒死」了。**
加密货币的请求要串行 + 限速，早期写法是全局一条链：

```js
chain = chain.then(async () => { /* 限速 + 发请求 */ });
return chain;                     // ❌ 业务错误会污染 chain
```

只要**有一次**请求抛错（429 / 超时 / 被墙），`chain` 就永久变成 rejected 状态，
之后**每一次** `await throttle()` 都立刻抛错 —— 表现就是「加密货币从某一刻起再也拉不到行情」。
现在链上只挂「已消化异常」的版本（`run.then(() => {}, () => {})`），
业务错误由返回值单独抛给调用方。

**8. 更新行情时把整个数据层锁死了 87 秒。**
`store.js` 用**一条串行队列**同时串行化读和写，而更新动作原本写在
`mutate()` 事务里 —— 于是联网的 87 秒里，`GET /api/state` 被堵了 87 秒
（实测 19 秒才返回一次），前端遮罩上的进度条因此一直停在第 0 步、
那个圈看起来就像「卡住不转」。

现在改成：**事务外**读快照 → 在快照上跑更新 → 一次极短的事务合并落盘。
合并时只搬「行情 / 统计」字段，所以更新期间你在界面上改的数量、成本、备注不会被覆盖。
实测更新期间 `/api/state` 从 19283ms 降到 ~30ms。

**9. 一个非法 symbol 毁掉整批查询。**
Binance 的批量报价接口只要收到一个不存在的交易对，返回的是
`HTTP 400 {"code":-1121,"msg":"Invalid symbol."}` —— 整批都拿不到，不是跳过那一个。
而 CoinGecko 的 id `tether` 正好会拼出不存在的 `USDTUSDT`。
现在：稳定币显式换成另一种稳定币计价、候选交易对按交易所的交易对清单校验、
并且每 60 个一批（某一批出问题最多只毁掉一批），必要时逐个降级重试。

**10. 按钮上的旋转指示器被挤到了第二行。**
`.btn-seal[disabled] { display: grid }` 这一句让按钮变成了「1 列 2 行」的网格容器：
文字占第一行，11px 的指示器被放到第二行，再被 `overflow: hidden` 裁掉 ——
看起来就是「更新时那个圈转得不对劲」。改成 `inline-flex` 居中单行后正常。
（这类问题的实测手段：在无头浏览器里读 `getBoundingClientRect()`，
比较指示器与文字的中线是否在同一行。）

**11. 遮罩上的加载环细得像一根头发。**
`.busy-seal::after` 原本是 `inset: -9px` + `border: 1.5px solid transparent` 只留 `border-top-color`。
问题有三个：1.5px 的边框在深色背景上偏细；方章是 3px 圆角而环是 6px，
两者圆角对不上、转角处直接插进红色方块里；再加上「只有上边」的方框本身就不像圆环 ——
用户的原话是「有一条杠一直在图标周围转」。
现在改成方形盒子上叠圆形 `mask` 裁出真正的圆环（`inset: -11px`，1.5px 线），
并用 `conic-gradient` 把色彩区间压在可见的那一段里，避免暗色尾巴糊在深色背景上。
判断依据是实测截图：把旋转动画用 Web Animations API 停在 0°/45°/…/315° 逐帧比对。

**12. 「屏蔽」把成本价清掉了。**
第一版实现为了让屏蔽项「不显示旧价格」，把行情字段（现价、净值、涨跌、走势）连同
`baselinePrice` / `lastUpdate` 一起清成 `null`。结果用户取消屏蔽后发现
**成本价、均价全变成 0**，必须再点一次「更新行情」才能找回来 —— 反馈是
「屏蔽了之后把成本价搞没了，应该是先暂存起来」。

这是把「不参与统计」和「没有数据」混为一谈了：
**合计口径**（`aggregate((r) => !r.hidden)`）已经能把屏蔽项排除干净，
根本不需要动它的数据。改成只翻转一个 `hidden` 布尔值之后：
持仓、成本、行情全部原样保留，取消屏蔽立刻还原。
验证方式是对屏蔽→更新→取消屏蔽做**逐字段 JSON 比对**（除 `updatedAt` / `hidden` / `weight` 外必须完全一致）。

## 已知边界

- **只做 A 股与公募基金**（港股 / 美股未接入，数据模型预留了市场字段）；
- 加密货币**没有做定投**（按需求只在基金板块实现），也没有多币种账户、手续费、分红再投的精算；
- 定投按「已公布的净值日期」逐个交易日结算，**不预测、不补未来**；
- 图标生成与启动器编译依赖 Windows（.NET Framework 的 `csc.exe`）；服务本身跨平台，非 Windows 可直接 `npm start` 用浏览器访问；
- 实时行情有数十秒到数分钟延迟，非交易时段显示最近一个交易日的收盘价 / 净值。
